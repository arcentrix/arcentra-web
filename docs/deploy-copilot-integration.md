# Deploy and Copilot integration status

The earlier unavailable-only placeholders have been replaced by bounded backend integrations in this change set.

- Copilot now supports server-configured OpenAI-compatible and Anthropic adapters, authorized run-log and registered text-code artifact selection, a redacted server-prepared preview, per-request data-sharing approval, one read-only analysis and cancellation. A separate default-off project capability adds up to three explicitly typed GitHub.com source files from an available job's Agent-reported initial checkout commit. Source-only selection works; preview and result evidence include the job, repository, commit, path and blob identity. This does not read the current workspace or attest to what was built. Older or unsupported jobs remain unavailable. Provider analysis remains unavailable until an operator explicitly configures credentials, models and project scope. See [Copilot flow and limitations](copilot-read-only.md), including preview/replica affinity and validation boundaries.
- Deploy now lists real project environments and release history through the deployment backend. Live Kubernetes access still requires an explicitly configured operator target. Creation, execution and observation are separate product actions; no live cluster or rollout is fabricated.
- Neither integration was configured with production credentials by this implementation. Unit fixtures do not constitute a live GitHub, model-provider, browser, or cluster acceptance test.

Conversation history, arbitrary repository/URL browsing, agent-workspace reads, and model-driven mutation tools are not implemented. Existing Build and Agents navigation remains available. Selection or scope changes clear Copilot preview and consent; closing or navigating away from its drawer also cancels pending work and clears prepared context.
